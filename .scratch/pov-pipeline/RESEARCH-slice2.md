## 1. HARD CONSTRAINTS (HIGH-confidence, corpus-attested or repo-measured — design MUST obey)

**Costume/identity referencing**
- Costume fidelity requires a dedicated reference, separate from face/identity refs. Converging sources: Seedance's own slot system separates identity (slots 1-3) from costume (slots 4-5) — `ai_video_resources/video_model_system_guide.md:416`; source-ranking puts official settei/turnarounds above key art above frame extracts — `reference-material-playbook.md:44-51`; explicit rule "costume/prop detail crops as SEPARATE refs, not more face shots" — `reference-material-playbook.md:178`. [costumed-limbs]
- A new costume/appearance STATE (e.g. civilian → transformed) should be built as its own reference set, not an edit of the old one. Higgsfield Elements practice: every new appearance change (scar/energy-glow/costume) gets its own new Element rather than modifying the old — `lanshu-awesome-ai-video-kit/methodology/19-seedance-masterclass-round3.md:89`. [costumed-limbs]
- The costume-added sheet must be the START-FRAME anchor, not just prose-referenced, or the costume piece can vanish mid-scene ("helmet suddenly disappears" fix: use the with-helmet sheet as start frame) — `15-seedance-masterclass.md:377`. [costumed-limbs]
- On a transformation shot, redescribe the costume verbatim on every shot it appears in and add an explicit lock clause ("Do not alter clothing category or primary color") or wardrobe reverts toward the pre-transformation baseline — `ai_video_resources/OpenMontage/.agents/skills/seedance-2-0/SKILL.md:229`. [costumed-limbs]
- Fine costume detail (emblems, buckles, seams) drifts across shots even when identity/face holds — low resolution forces the model to invent it differently each generation — `reference-material-playbook.md:56`. [costumed-limbs]
- Generic (non-costume-specific) hand-deformation risk exists at baseline: anchor hands to objects, use medium shots not extreme close-ups — `video_model_system_guide.md:445`. This is NOT attested as compounding with costume complexity — treat as an adjacent baseline risk. [costumed-limbs]

**Reference sourcing**
- Source ranking, best→worst: official character sheets/settei > official key art/promo > lossless frame extracts > product photography > streaming screenshots > fan art > upscaled/re-compressed web rips (never) — `reference-material-playbook.md:44-51`. [ref-sourcing]
- Multi-view reference sheets are safe iff exactly ONE panel contains the identity-bearing region (face); other panels (full-body, back) must have it removed/de-emphasized — reconciles an apparent conflict between `video_model_system_guide.md:390-400` (co-equal 3-face sheet) and the vendor root-cause doc `08-避坑12问.md:11-21` (multi-view worsens ID drift, mechanism: face-region-too-small-a-proportion → under-weighted). Reconciliation source: `Dan Kieft Three-Step Film Workflow.md:18-46`, confirmed by `Dan Kieft Advanced Techniques (OpenArt).md:52-71`. See section 3 — this is presented here as settled, not a live fork. [ref-sourcing]
- 3-angle+ coverage order: front, ¾ (highest single-view information), profile, full-body-front (proportions+costume), back only if design has back detail — `reference-material-playbook.md:64-78`. [ref-sourcing]
- Reference-count economics: steep gains 1→3 refs, moderate 3→6-8, flat beyond that per subject/style; diversity beats count; negative returns are real (one bad ref among five can cost more than dropping to four clean) — `reference-material-playbook.md:118-130`. Target ~3-5 identity refs, rest of budget on scene/costume/style — `reference-material-playbook.md:131-133`. [ref-sourcing]
- Neutral-expression refs are mandatory — a smiling/expressive ref reshapes the render toward that expression regardless of prompt instruction ("refs beat prompts"): repo-measured as BUG-030, root cause cited to `reference-material-playbook.md:59-60` — `bugs.md:1010-1047`. [cli-refs-video]
- Photographic references of a real, visible human face trigger the Higgsfield NSFW/moderation block (exit 3, refunded); the same prompt+scene with NO refs renders fine — BUG-012, `bugs.md:670-686`. Stated workaround category: fictional character art / 3D renders / illustrated sheets, not photographic — `video_model_system_guide.md:440`. Filter-evasion techniques are explicitly out of policy — `bugs.md:683-684`. This makes non-photographic official-art sourcing doubly load-bearing (also satisfies the top of the source ranking above). [ref-sourcing]
- Style/artifact contamination: if the target register (e.g. clean modern render) doesn't match the ref's actual style (e.g. photographic/vintage), output drifts toward the ref's style unless explicitly constrained in the prompt, or the ref must be pre-converted to the target style before use — `08-避坑12问.md:52-60`. Baked-in capture artifacts (compression, grain, watermark ghosts) sit in the same visual channel as design and get reproduced; the model adds, never strips, such qualities — `reference-material-playbook.md:57,107`. [ref-sourcing]
- Multi-identical-figure duplication ("twins") is a documented pitfall of multi-view/turnaround reference sheets — `08-避坑12问.md:79-101`. This repo's preventive fix, already shipped: refs are headshot + full-body ONLY, 2/character, turnaround sheets archived — `render_taste_test/DECISIONS_LOCKED.md` L9 (lines 243-244); a standing `subject_uniqueness` prompt constraint is applied to motion-kind jobs — `config/render_rules.yaml:442-445`. [cli-refs-video]

**Higgsfield/Seedance mechanics (repo-measured)**

[cli-refs-video]
- Measured caps: `max_image_references: 9` (counts start/end image too), `max_reference_files_total: 12`, `max_prompt_chars: 3200` — `config/render_rules.yaml:109-133`. [cli-refs-video]

Failed/rejected jobs are refunded regardless of ref presence — `render_taste_test/DECISIONS_LOCKED.md` line 98; `executor.py:310-313`. [cli-refs-video]

**Attack/beam vocabulary and content filtering**
- Corpus beam/energy-attack vocabulary is uniformly kinetic (crackle, arc, surge, erupt, discharge, release, fracture) — never "glow"/"glimmer" — verified by full-read of the corpus's beam examples (`sd-067`, doc 15, doc 19). The repo's `glow_glimmer` kill-list substitution (`config/render_rules.yaml:606-608`) was tuned for a static continuously-brightening object, not a pulsing attack-beam; use the corpus's kinetic verbs for beam luminance rather than routing it through glow/glimmer language. [beam-vfx]
- Attack-on-a-target framing is a documented content-filter risk. Doc 19's substitution table (`kill/brutal/attack → dramatic energy clash`, `punch/slash → powerful forces meeting`, `blood → epic visual impact`, plus action-wrapping in narrative context) is already wired into this repo's `scene_lane` dialect — `19-seedance-masterclass-round3.md:144-151`; `config/render_rules.yaml:149-156`. **Code-verified gap: the POV compiler's `_scrub()` does not read or apply `scene_lane`'s sensitive-words/action-wrapping substitution at all — it only reads `dead_intensifiers`, `cinematic_without_specifics`, and `glow_glimmer` from `pov_grammar.kill_list`** — confirmed by reading `src/generation/pov/compiler.py:102-249` and the full `pov_grammar.kill_list` block (`render_rules.yaml:598-608`). Slice ② design MUST close this gap before compiling a "fire the beam at [kaiju]" beat — it is currently unaddressed, not a deliberate scope choice. [beam-vfx]
- The existing money-shot contract (`.scratch/pov-pipeline/issues/07-money-shot-contract.md`) explicitly lists "Slice ② (IP topics with reference assets)" as Out of Scope (line 139). Slice ② needs its own money-shot capture mechanism for the beam payoff — the fix built for slice ① does not cover it. [beam-vfx]

**Camera grammar conflict (already-locked POV rules)**
- Slice ①'s locked POV grammar requires a single continuous take with no cuts and no camera-angle switches — `anti_drift_constraint` / `continuous_take_constraint`, `config/render_rules.yaml:577-582` (probe-validated, sourced `15-seedance-masterclass.md:163-169,385`). The corpus's only documented technique for masking a transformation via a light-burst/flash is built ACROSS A CUT — a flash ends shot 1, a new shot/angle opens on the post-change state, generated as SEPARATE runs assembled in post-edit — `Dan Kieft Cinematic Seedance Updated.md:361`; `Dan Kieft Film Director Brain.md:227`. **These two are in direct tension: the corpus's only flash-masking technique requires exactly the shot boundary the locked POV grammar forbids.** Slice ② cannot import this technique as-is under the current no-cut POV constraint. [transformation] × [locked repo rule]

## 2. OPEN RISKS — corpus cannot answer, need a paid 480p probe (measured rate: 30cr/10s clip, `render_taste_test/pov_probe/PROBE_SHEET.md:9-11`)

1. **Does a beam/energy-attack VFX render correctly at all in POV register on our stack?** Zero watched-render evidence exists anywhere in this project or the corpus. The one concrete attempt (`output/pov/20260717_184048_kaiju_tokyo_beam_rerun_b1850b/`) compiled a beam beat but was archived unrendered, superseded before any watch — `render_sheet.md:3-8` in that directory ("SUPERSEDED 2026-07-17, NEVER RENDERED"). Timing, direction, and whether it renders as a coherent beam (vs. artifact/nothing) are all unknown. [beam-vfx]
2. **Does a mid-shot identity/scale change hold in ONE continuous generation, or does it morph?** Corpus pitfall: "if endpoints disagree on identity, wardrobe, or geography, the model morphs instead of transitions" — `image-video-director/03-video-prompting-techniques.md:37`. Corroborating (but architecture-stale) our-repo evidence: the half-state-deform taxonomy (`project_render_failure_taxonomy.md:27-34`) was built against the now-deleted still-first i2v pipeline; the underlying physics finding (an "about-to" half-state renders as literal deformity) is plausibly transferable but untested on the current single-gen architecture. Adjacent evidence from a different impossible-held-end-state class (draining pool) shows plain single-generation prose was insufficient even for a simpler physical anomaly — required model escalation to hold — `render_taste_test/DECISIONS_LOCKED.md:35-36`; `config/render_rules.yaml:69-72`. No corpus or repo example ever attempted a body/costume/scale transformation in one unbroken take. [transformation]
3. **Does an in-take (no-cut) flash-whiteout work as a transformation mask?** Only the cut-based version is documented (see section 1's conflict). Whether whiting out and un-whiting-out within the SAME continuous shot (no angle change) can mask a transformation is untested anywhere. [transformation]
4. **Does a masked/suited photographic reference dodge the BUG-012 NSFW trigger?** BUG-012 only tested visible human faces. A rigid, fully-opaque mask covering the face is directionally plausible to not trigger the same mechanism (`bugs.md:678`: trigger = "photographic human-face pixels") but this is unverified inference, not a tested finding. Practical note: this risk is largely moot if slice ② sources non-photographic official art per section 1/4 — probe only if a photographic source becomes necessary. [ref-sourcing]
5. **Does the one-face-sheet mechanism (and the "twins" pitfall) apply the same way to a fully-opaque-mask subject with zero human face?** A rigid mask has no expression to disagree across angles (structurally weaker averaging risk than a human face), but this is mechanism-grounded inference, not corpus-tested. [ref-sourcing / costumed-limbs]
6. **Does a POV-cropped (wrist-down, no-face) costume reference transfer as usable source material?** Every costume-sheet method in the corpus is built and demonstrated in third-person/full-body framing; none tests a reference cropped the way the POV camera will actually see it. [costumed-limbs]
7. **Does hand-deformation risk compound with costume-detail fidelity requirements (gloves, seams, color-timer)?** The two risk classes are each attested separately, never jointly. [costumed-limbs]
8. **Does a held-pose-then-discharge beat structure (cross arms, hold, then fire) work, or does it need two explicit sub-beats?** Every corpus release pattern reviewed is continuous-crackle or motion-triggered ("hands crackle with...", "slamming both hands down releasing..."); none shows a static pose triggering a discharge. Inference from absence, not a tested finding. [beam-vfx]
9. **Does explicit beam-origin language (e.g. "from her crossed wrists") need to survive script compression, or can it be inferred from an earlier pose beat?** Every working corpus precedent keeps the origin noun explicit and load-bearing in the same clause as the release verb; the one repo draft that separated origin from release (`output/pov/20260717_184048.../`) had the origin phrase dropped by beat-list compression — but this was never rendered, so it's descriptive of a risk pattern, not a proven failure. [beam-vfx]
10. **Does the `style_register` clause's "No 3D, no cartoon, no VFX aesthetic" negation (`render_rules.yaml:589-590`) fight against rendering a VFX beam?** That negation is bolted on from an unrelated source (doc 15:381's anti-plastic-skin fix), not from anything about beam VFX, and is itself flagged in the repo's own evidence field as "CORPUS-ONLY as of 2026-07-17 — not yet watched." [beam-vfx]
11. **Is there a real mechanism needed for the "character speaks into the lens" situation beyond the documented eye-beat craft rule?** The PRD names a "render gate" for this (`.scratch/pov-pipeline/PRD.md:67`) that has no corpus basis (see section 5) — whether it needs teeth-style reroll-and-select handling or new craft rules is unresolved and would need the same kind of empirical probe that solved the continuous-take and teeth issues in slice ①. [speak-into-lens]

## 3. CONTRADICTIONS / TENSIONS (stated neutrally, both sides cited)

**A. Reconciled, not live — multi-view sheets vs. single-face rule.** `video_model_system_guide.md:390-400` prescribes a co-equal 3-angle FACE sheet (front/¾/profile). `08-避坑12问.md:11-21` (and `:79-99` on the "twins" pitfall) says multi-view material worsens ID drift and causes duplicate-subject readings, root-caused to face-region-too-small-a-proportion. `Dan Kieft Three-Step Film Workflow.md:18-46` reconciles both: the discriminator is number of FACES, not number of ANGLES — multiple angles are safe iff exactly one panel contains a face. This reconciliation is confirmed by `Dan Kieft Advanced Techniques (OpenArt).md:52-71`. Presented here as settled corpus guidance (used in section 1), not an open fork.

**B. Same source, opposite framing across two research threads — the astronaut-helmet costume method.** [costumed-limbs] cites `15-seedance-masterclass.md:112-116` as a valid, usable build method: generate a base multi-angle sheet, then edit the costume piece onto every panel. [ref-sourcing] cites the SAME lines as (i) superseded, because its base step is the co-equal multi-view face sheet that item A above flags as contradicted by the vendor doc, and (ii) non-transferable to Ultraman as written, because its explicit instruction "make sure the face is still visible, no light reflection on the helmet" assumes partial/see-through coverage — Ultraman's mask is fully opaque with zero visible human face. Reconciliation for slice ② design: the COSTUME-ADDED-SHEET-AS-START-FRAME lock (the mechanism that fixes vanishing costume pieces) survives as a hard constraint (section 1); the method's "keep face visible" instruction and its co-equal multi-view base step do not apply to a fully-opaque mask and should not be imported as written.

**C. Repo-config tension, single-researcher-flagged (not cross-researcher) — glow/glimmer kill-list and "No VFX aesthetic" clause.** [beam-vfx] flags that `render_rules.yaml:589-590`'s style_register clause splices two different corpus sources together: sentence 1 is verbatim sd-067 (ends "...practical VFX feel," no negation); sentence 2's "No 3D, no cartoon, no VFX aesthetic" is bolted on from an unrelated pitfall fix (doc 15:381, plastic-skin monster texture) with zero connection to beam/attack VFX. The result: every action-register POV prompt currently instructs the model to suppress "VFX aesthetic" while also asking it to render an energy beam, which is VFX. This is a repo-authoring inconsistency identified by one researcher reading two sources side by side, not a disagreement between researchers — flagged HIGH confidence on the mismatch, UNVERIFIED on actual render impact (nothing watched).

**D. Corpus technique vs. locked repo grammar — flash-masking requires a cut, POV grammar forbids cuts.** See section 1's last bullet. This is a real conflict between what the corpus documents as the ONLY flash-masking technique (`Dan Kieft Cinematic Seedance Updated.md:361`, `Dan Kieft Film Director Brain.md:227`) and this repo's own locked, probe-validated no-cut/no-angle-switch POV rule (`render_rules.yaml:577-582`). No corpus or repo source resolves it either way for an in-take variant — carried to section 2 as open risk #3.

**E. Different use-case, flagged as a trap not a rule to import.** [costumed-limbs] flags `Dan Kieft Film Director Brain.md:137` ("costume by reference, not by tag... describe it in words, state it's an original variation, not a copy") as written for ORIGINAL-character costume inspiration (likely legal/creative-distance reasoning), not canon-IP reproduction. If applied uncritically to Ultraman it would work against slice ②'s exact-match goal. This is not a contradiction between researchers — only one thread surfaced it — but it is a real corpus rule that points the wrong direction for this use case and needs an explicit product decision to override, not silent adoption.

## 4. CONCRETE ASSET RECIPE — masked/suited canon character (evidence-supported)

1. **Source non-photographic official art only**: settei/production turnarounds (top tier) or official key art/figure renders (second tier) — never live-action screencaps of an actor-in-suit, which rank low (#5, streaming-screenshot tier) on the quality ranking AND are the exact category BUG-012 measured as NSFW-triggering when photographic and face-visible. `reference-material-playbook.md:44-51`; `bugs.md:670-686`; `video_model_system_guide.md:440`. This single sourcing choice satisfies quality, sidesteps the NSFW question (section 2 risk #4 becomes moot), and avoids vintage-artifact canonization.
2. **~3-5 identity refs total**, prioritizing diversity of angle/information over raw count; do not pad with near-duplicate frontals. `reference-material-playbook.md:118-133`.
3. **One panel carries the identity-bearing region (the mask/helmet close-up) at high resolution; other panels (full-body, back) de-emphasize or omit it**, applying the reconciled one-face-region rule (section 3.A) to the mask instead of a human face. **This substitution — face region → mask region — is a mechanism-grounded extrapolation, not a corpus-tested claim (MED confidence)**; no corpus source builds a sheet for a subject with zero human face. `Dan Kieft Three-Step Film Workflow.md:18-46`; `08-避坑12问.md:11-21`.
4. **Coverage order**: front, ¾, profile (mask/head only where the identity region appears), full-body-front for proportions + costume, back only if the suit design has back detail. `reference-material-playbook.md:64-78`.
5. **Build a separate costume-added sheet variant as the START-FRAME anchor** for the transformed state — do not rely on prose alone to hold the costume; use the with-costume sheet as start frame to prevent mid-scene vanishing, per the helmet-disappearing fix. `15-seedance-masterclass.md:112-116,377`. Per section 3.B, import the START-FRAME-LOCK mechanism only, not the method's face-visibility assumption.
6. **Treat the transformed state as its own Element/reference set, not an edit of the civilian-state refs** — Higgsfield Elements practice for appearance-state changes. `19-seedance-masterclass-round3.md:89`.
7. **Bind all refs positionally** — `"{name} is the character shown in image1, image2"` — never re-describe appearance in prose; the key-art alone carries appearance. `render_rules.yaml:138`; `adapter.py:101-123`.
8. **Use neutral, non-smiling reference expressions** where the source allows a choice (settei often is neutral by nature) — a smiling/expressive ref reshapes the render toward that expression regardless of prompt instruction. `reference-material-playbook.md:59-60`; `bugs.md:1010-1047` (BUG-030).
9. **Stay within measured caps**: ≤9 image refs (start/end frames count against this), ≤12 total reference files, ≤3200-char prompt. `render_rules.yaml:109-133`.
10. **Do NOT treat this recipe as validating the full render technique** ("canon-costumed POV limbs," POV+transformation combined). The recipe above is the reference-asset side only; the render outcome (does it actually hold on a POV camera, does the beam fire correctly, does the transformation morph) is unproven and belongs entirely to section 2's probe list, per the house rule against inventing untested render techniques.
