## Issues Found (non-blocking)

**1. `extractor_version` + `extractor_model` fields in Blueprint Pydantic schema**
Sonnet hallucinates values ("gpt-4o", "gpt-4.1", "1.0") — these are DB-level metadata, not extracted content. Real values set correctly in `BlueprintRecord` ORM row by `save_blueprint()`. Blueprint JSON stored in `blueprint_data` column contains wrong values for these two fields.
Fix: remove both fields from `Blueprint` Pydantic schema in v2. Requires `EXTRACTOR_VERSION` bump + re-extraction.

**2. `primary_emotion` calibration**
Human grader noted primary_emotion sometimes off. No kappa scorer exists for this field. Risk: noisy ML feature in P4. Mitigation: add `kappa_primary_emotion` scorer before P4, or drop field from schema in v2.

**3. No-transcript items (music/aesthetic videos)**
93% of DB items lack transcripts. Most are music-only — no transcript by design, not a data gap. Text-only extractor still produces valid Blueprints from caption + hashtags + stats (confidence correctly self-reported at 0.35-0.42). Human grades on these items not isolated — overall avg 4.05 suggests text-only path acceptable even without transcripts.
Vision spec (2026-05-08) deferred pending P2 + future data showing quality gap.

**4. `load_dotenv` missing in scripts**
`run_self_agreement.py` lacked `load_dotenv` — caused 100% skip rate on first T12 run. Fixed same session. Pattern: all `scripts/` entrypoints need `load_dotenv(PROJECT_ROOT / "config" / ".env")` before src imports.
