# Lock 8 Tier 1 Blueprint fields to Literal enums in v3.1

The eight open-string Tier 1 fields shipped in v3 (`hook_type`, `share_hook_type`, `comment_bait_type`, `pacing`, `loop_type`, `audio_type`, `visual_complexity`, `color_mood`) close to `Literal[...]` enums in v3.1. All eight pass the ADR-0002 lock criteria — Cohen's kappa ≥ 0.6 on a 30-item self-agreement re-run plus cross-niche reuse and ≤7 values — against the 438-item v3 corpus (185 surreal_hyperreal + 84 anime_ai + 86 horror_ai + 83 brainrot).

## Locked value sets

```
hook_type:         visual_shock, identity_signal, curiosity_gap, uncanny_reveal, nostalgia_trigger
share_hook_type:   technical_awe, shocking, identity_signal, makes_friends_laugh
comment_bait_type: relatable_moment, controversial_claim, open_ending, question_to_viewer
pacing:            moderate, slow_atmospheric, fast
loop_type:         none, hard_cut, seamless_visual, narrative_loop
audio_type:        trending_audio, original_voiceover, ambient_sfx, music_only
visual_complexity: moderate, minimal, dense
color_mood:        vivid_saturated, desaturated, warm_muted, cool_clinical, neon
```

## Kappa evidence (30-item self-agreement, 2026-05-14)

```
audio_type        0.949
share_hook_type   0.892
color_mood        0.862
hook_type         0.800
comment_bait_type 0.795
visual_complexity 0.774
pacing            0.655
loop_type         0.639
```

All ≥ 0.6 threshold from ADR-0002. `pacing` and `loop_type` are borderline; revisit if extractor changes reduce them below threshold.

## Cross-niche drops

Two values met the kappa criterion but failed the cross-niche reuse rule and were excluded from the locked set:

- `pacing.chaotic_cuts` — appears only in `brainrot` (3 items)
- `audio_type.silent` — appears only in `horror_ai` (1 item)

Including single-niche values would bake niche-specific shape into a deliberately niche-agnostic schema (see CONTEXT.md `Niche` entry). The 4 affected items re-extract under the locked schema; ~$0.04 cost.

## Consequences

- v3.1 eval gate kappa-scores all 10 Tier 1 fields (8 newly locked + `primary_emotion` + `duration_band`). Coverage of the eval gate roughly quintuples vs. v3.
- 50 of 438 existing v3 Blueprints (~11.4%) carry singleton or rare values not in the locked set (`process_reveal`, `tutorial_promise`, `keyword_trigger`, `controversial_claim` under share_hook_type, etc.). These items must be re-extracted under v3.1; the rest reparse from the cache without an LLM call once the cache is populated (see ADR-0004).
- Adding a new value to a locked Literal is cache-safe and free (see ADR-0004). Future scrapes that produce a new value with kappa ≥ 0.6 and cross-niche reuse can lock it by extending the Literal.

## Considered alternatives

**Keep `chaotic_cuts` and `silent` in the locked set despite single-niche appearance** — rejected because ADR-0002 explicitly tied lock-eligibility to cross-niche reuse to keep Blueprint niche-agnostic. Allowing single-niche values now would erode the rule and invite further drift.

**Leave one or two fields open** (specifically `pacing` and `loop_type`, both borderline at ~0.65 kappa) — rejected because the eval gate cannot kappa-score open-string fields; leaving them open keeps a known noisy field outside CI coverage. Borderline kappa is monitored as a trip-wire instead.
